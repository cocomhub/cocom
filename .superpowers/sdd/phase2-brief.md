# Phase 2: 逆向追踪配置链路

## 目标

从最新 commit（当前 HEAD）从消费方逆向追踪每条配置链路，与 v0.0.57 对比，记录异常。

## 方法

1. 读取 Phase 1 的输出文件 `phase1-v0.0.57-config-inventory.md`
2. 对于其中每个配置键，在当前代码中搜索其消费方（`viper.Get*` 或 `config.Get().Field`）
3. 追踪每条链路的完整传导路径
4. 与 Phase 1 的记录对比，标记以下异常：
   - **未找到**: v0.0.57 中存在的配置键在当前代码中找不到
   - **实现中断**: 传导链路断裂（如 SetDefault 存在但无消费方，或消费方存在但无 SetDefault）
   - **路径变更**: 键路径发生了变化（如 `http.enable_proxy` → `download.enableProxy`）
   - **类型不匹配**: 默认值类型与消费方期望类型不一致
   - **额外键**: 当前代码中存在但 v0.0.57 中不存在的配置键
