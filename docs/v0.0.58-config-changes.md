# v0.0.58 配置与行为变更摘要

> 本文档记录 v0.0.58（review 分支 d9087b1..HEAD）对生产代码的**破坏性/行为变更**，供升级者在升级前核对。完整配置键说明见 `docs/config.md`。

## 一、破坏性变更（升级需注意）

### 1. `server.ratelimit.burst` 删除
- **原因**：`ulule/limiter` 通过 `rate.Limit`（rps）控制桶容量，burst 参数从未被实际使用，保留只会造成"配置了却无效"的欺骗。
- **影响**：若旧配置含 `burst` 键，`config migrate` 会将其标记为冗余；`server.ratelimit` 只保留 `enabled` + `rps`。

### 2. 管理端鉴权键迁移
- 旧键 `admin.token`、`admin.allow_remote`、`debug.allow_remote` 统一迁移到 `server.admin.token` / `server.admin.allow_remote`。
- `config migrate` 执行：新键已存在且与旧键值不同 → `conflictError`（迁移失败，需人工决策）；否则按顺序覆盖并写回新键。
- **注意**：两个旧 `allow_remote`（`admin.*` 与 `debug.*`）同时存在且目标值不同时也会触发 conflictError。

### 3. `log.disableTraceID` / `server.scheduler.cocoma_archiver.cid_regex` / `comic.verify.concurrent` 死键接线
- 此前仅为 `SetDefault` 注册、无实际消费；现 `cid_regex` 与 `verify.concurrent`、`disableTraceID` 真正生效（如果它们本就该有）——若你的旧配置未显式设置，它们的默认值与新逻辑一致。
- `comic.verify.task_buffer_size`：`validate` 已补上 >0 校验。

### 4. 配置校验失败即启动失败（fail-fast）
- 不符合校验（如 `comic.verify.concurrent` <= 0、CORS 配置含非 http(s) scheme、端口非法）现在**启动即失败**，而不是带错误配置继续运行。
- `config migrate` 对已存在新键做冲突失败（原子写盘：临时文件 fsync + rename）。

### 5. `server.listen.http.addr` 三空 fail-fast
- addr 与 TLS/unix_path 全空时拒绝启动（此前可能静默回退全接口监听）。

## 二、行为修正（非破坏）

- `pkg/archive/manager` replicate：失败时状态持久化 healthy=false；ETag 严格一致才算上传成功（有界重试）。
- `verify` 任务：修复循环有上限（maxFixRetry=3），任务终态不再残留 Pending。
- `$exists`/`$ne` 整型与 bool 混用安全转换（不再 panic）。
- 首页 filters/分页/排序对齐 Mongo 与 MemoryStorage。
- `archive` 7z 探测补 Windows `C:/Program Files/7-Zip/7z.exe`（无 PATH 注册时不再误报"7z 未找到"）。

## 三、删除的纯死代码/API

- `middlewares.RateLimit` 签名由 `(rps, burst)` 改为 `(rps)`（仓库内唯一调用点已同步）。
- logging 删除 `NewDevelopmentConfig/NewProductionConfig/NewStdConfig/AppName/GlobalCallerSkip`（全仓库零引用）。
- baidupcs 死码（`optionalBoolValue` 等）已清。

## 四、不受影响

- `comic.Storage` 接口方法集不变（内部实现修复）。
- vidéo/custom/onecomic/setting/tag 等各默认存储注入模式不变。
- 构建 / 发布 / 配置加载链不变。
